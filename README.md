# EduBridge

Platform deteksi dan pengurangan learning gap **Matematika kelas XI SMA**, melalui CDA sebelum/sesudah pembelajaran dan inferensi CDM **P-DINA**. Alur: **pretest → diagnosis awal → pembelajaran di kelas → penguatan konsep → posttest → perbandingan dalam siklus yang sama**. Peran: siswa, guru, admin.

## Arsitektur

Guru dan admin dapat membuka **Kelola materi** (`/kelola-materi`) untuk membuat, mengedit, menerbitkan, atau menghapus materi penguatan. Guru mengelola materi kelasnya; admin juga dapat membuat materi umum untuk semua kelas. Draf hanya terlihat oleh pengelola. Ikon ilustrasi dipilih otomatis dan konsisten berdasarkan judul/topik, menggunakan enam gaya ikon katalog yang sama.

Materi mendukung beberapa bagian, rumus LaTeX, penjelasan bertahap, contoh berlangkah, miskonsepsi, dan latihan mandiri. Tombol **Sesuaikan untuk kelas** di katalog menyalin materi topik menjadi materi penguatan yang dapat diedit. Materi terbit tampil di katalog siswa dan halaman topik terkait. Penguatan dipetakan ke enam topik asesmen yang sudah dikalibrasi; pembuatan atau penghapusan materi tidak mengubah bank soal, parameter P-DINA, XP, atau hasil pre/posttest. Materi tambahan boleh dibaca kapan saja, sedangkan asesmen tetap mengikuti fase kelas.

API autentikasi: `GET/POST /api/materials`, `GET/PATCH/DELETE /api/materials/:id`. Pembaruan dan penghapusan membutuhkan `version` terbaru untuk mencegah perubahan saling menimpa. Mutasi menggunakan CSRF, validasi, transaksi, audit, dan penghapusan logis. Tabel `materials` dibuat otomatis saat backend membuka database, termasuk pada database yang sudah ada. Tes fitur tersedia di `server/test/materials.test.js` dan `tests/materials.spec.js`.

**Draf materi dengan AI:** di editor, pilih topik dan kelas, isi arahan opsional, lalu gunakan **Isi semua bagian dengan AI** (1–6 bagian) atau tombol AI pada masing-masing bagian. Penggantian isi yang sudah ada meminta konfirmasi. Hasil mengisi penjelasan, contoh, penjelasan bertahap, miskonsepsi, dan latihan; tetap berupa draf yang bisa diedit. Kegagalan AI atau pembatalan tidak menimpa tulisan manual.

Guru/pengelola wajib memeriksa rumus, konsep, contoh, dan jawaban latihan, lalu mencentang **Saya sudah meninjau dan memvalidasi kebenaran seluruh materi** sebelum menerbitkan. Backend menolak publikasi tanpa validasi (`422`), menyimpan peninjau/waktu/hash isi, dan membatalkan validasi ketika isi atau cakupan kelas/topik berubah. Ini adalah konfirmasi peninjauan manusia, bukan klaim bahwa LLM membuktikan kebenaran matematika. Materi manual baru juga memakai konfirmasi ini sebelum terbit; materi lama tidak diubah otomatis.

Gunakan **Pratinjau bagian seperti tampilan siswa** untuk membaca hasil lengkap dengan rumus KaTeX dan mencoba pembahasan latihan sebelum memvalidasi. Pratinjau memakai renderer yang sama dengan halaman siswa.

Generator memakai Gemini dari `GEMINI_API_KEY` dan `GEMINI_MODEL` yang sudah dikonfigurasi. Opsional: `GEMINI_MATERIAL_MODEL` untuk model materi yang berbeda dan `GEMINI_MATERIAL_TIMEOUT_SECONDS` (default 70). Tidak membutuhkan retraining PDINA. Endpoint aplikasi: `POST /api/materials/generate` dengan `topicId`, `classId`, `title`, `sectionTitle`, `instructions`, dan `blockCount`. Endpoint FastAPI: `POST /v1/materials/generate`; payload, respons, contoh, batas field, dan error tersedia di Swagger `/docs`. Endpoint FastAPI memakai service key; hanya guru/admin dengan sesi dan CSRF dapat mengakses generator melalui aplikasi. Tidak ada data siswa atau bank soal asesmen yang dikirim ke generator.

Uji live terisolasi: `node scripts/check-material-generation.mjs --confirm` membuat satu panggilan Gemini nyata dan memeriksa simpan draf serta gerbang publikasi memakai database dalam memori. Hasil ringkas dan contoh draf disimpan di `artifacts/material-generation-live.json` dan `artifacts/generated-material-preview.json` (lokal, diabaikan Git). Tanpa `--confirm`, tidak ada panggilan provider. Tes otomatis tanpa biaya memakai mock provider, termasuk keluaran tidak valid, gangguan provider, pembatalan, dan validasi ulang.

Tambahkan `--blocks=3` untuk menguji satu materi lengkap dengan tiga bagian (rentang 1–6 bagian, tetap satu panggilan provider per eksekusi).

- `client/`: React/Vite, jalur belajar, maskot, gamifikasi, materi, asesmen, progres, profil, tema terang/gelap tersimpan dalam cookie.
- `shared/`: aturan pemilihan ikon materi yang dipakai bersama frontend dan backend; disertakan dalam image Docker.
- `server/src/`: API aplikasi Node.js 24 + SQLite, autentikasi, otorisasi, sesi, kelas, asesmen, audit administrasi.
- `server/ml/web/`: FastAPI untuk PDINA, perbandingan pre/post, ringkasan siswa/kelas dan pendamping Gemini. Swagger/OpenAPI tersedia.
- `server/ml/cdacdm/`: implementasi P-DINA, CDA, Q-matrix, evaluasi dan narasi dari proyek AI asli.
- `server/ml/artifacts/` dan `artifacts_calculus/`: checkpoint dan hasil eksperimen asli, dipertahankan.
- `server/ml/artifacts_edubridge/`: checkpoint khusus instrumen aplikasi, kebijakan diagnosis dan evaluasi.
- `server/ml/instruments/edubridge.json`: instrumen privat, termasuk kunci; jangan dipublikasikan sebagai aset frontend.
- `server/ml/datasets/edubridge/`: data kalibrasi sintetis yang dapat direproduksi.
- `deploy/`, `Dockerfile`, `compose.yaml`: deployment HTTPS dengan reverse proxy.

Folder `ai` telah dipindahkan ke `server/ml` dan dihapus dari akar proyek. Dataset mentah EEDI dan prototipe Streamlit dipertahankan untuk penelitian; tidak disajikan oleh aplikasi produksi. Riwayat Git sumber dan `.env` impor diarsipkan di `server/data/` yang diabaikan Git. Kredensial impor **tidak digunakan otomatis**. Isi konfigurasi aktif hanya di `server/.env`.

## Menjalankan lokal

Memerlukan **Node.js 24+**, **Python 3.12**, npm, dan Google Chrome untuk tes browser.

Windows PowerShell:

```powershell
npm.cmd ci
py -3.12 -m venv server/.venv
.\server\.venv\Scripts\python.exe -m pip install -r server/ml/requirements-runtime.lock
Copy-Item server/.env.example server/.env  # hanya jika server/.env belum ada
npm.cmd run dev
```

Linux/macOS:

```sh
npm ci
python3.12 -m venv server/.venv
server/.venv/bin/python -m pip install -r server/ml/requirements-runtime.lock
cp -n server/.env.example server/.env
npm run dev
```

`npm run dev` menjalankan FastAPI terlebih dahulu, menunggu siap, lalu API dan Vite. `Ctrl+C` menghentikan proses yang dimulainya. Hentikan instance lama sebelum menjalankan stack baru.

| ------------------------ | ---------------------------------- |

| API aplikasi             | http://127.0.0.1:4000/api/health   |
| Kesiapan seluruh backend | http://127.0.0.1:4000/api/ready    |

Untuk menjalankan build frontend bersama kedua backend: `npm run build`, kemudian `npm start`; buka port **4000**. Layanan dapat dijalankan terpisah melalui `npm run dev:client`, `npm run dev:server`, dan `npm run start:ai`.

Gunakan `server/.env.example` sebagai acuan. Jangan memasukkan secret ke `client/`, variabel `VITE_*`, konfigurasi model JSON, atau Git.

## Instrumen, PDINA dan data

Aplikasi mempertahankan enam topik: komposisi/invers fungsi, lingkaran, statistika, peluang, matriks, dan transformasi. Ada **18 atribut, 180 soal pre/post**, masing-masing **15 soal per topik per fase**, serta 18 materi penguatan dengan contoh bertahap, miskonsepsi dan 36 latihan mandiri.

Checkpoint EEDI memakai 948 soal/57 konsep dan checkpoint kalkulus memakai 96 soal/13 konsep. ID soal, Q-matrix dan atributnya berbeda dari aplikasi. Memindahkan parameter keduanya ke soal aplikasi akan menghasilkan diagnosis yang tidak sah. Karena itu dibuat instrumen Indonesia sesuai aplikasi dan dilakukan **kalibrasi ulang yang diperlukan hanya untuk instrumen EduBridge**. Kedua checkpoint asli tidak ditimpa dan tetap dapat diakses lewat FastAPI.

Data baru memuat **2.000 siswa sintetis**, split berdasarkan siswa: 1.600 train, 200 validation, 200 test, seed `20261117`. Empat konfigurasi P-DINA dipilih dengan held-out log-loss validation; ambang dipilih hanya dari validation. Test dievaluasi setelah seleksi. Detail, sumber sintetis, batas penggunaan dan metrik tersimpan di `server/ml/artifacts_edubridge/model/model_card.json`.

**Kesiapan perangkat lunak berbeda dari validitas instrumen pendidikan.** Data sintetis menguji integrasi dan perilaku statistik model; tidak membuktikan validitas pada siswa Indonesia. Q-matrix, soal, ambang, dan rekomendasi perlu ditinjau guru, kemudian dikalibrasi/diuji menggunakan respons pre/post siswa nyata sebelum menjadi dasar keputusan akademik. Perubahan pre/post tidak membuktikan efek kausal intervensi.

Inferensi memakai checkpoint beku, **tanpa training saat request atau startup**. `simulated=false` berarti algoritme PDINA benar-benar dijalankan; `calibrationSynthetic=true` tetap menjelaskan asal kalibrasinya. Posterior penguasaan berbeda dari nilai kuis. Lima respons teramati per atribut diperlukan; respons kosong tidak dianggap salah. Label meliputi `mastered`, `not_mastered`, `uncertain`, dan `insufficient_evidence`; bukti yang kurang tidak dihitung sebagai gap.

Versi hasil mencakup fingerprint parameter dan kebijakan. Riwayat disimpan bersama snapshot soal. Perubahan teks, pilihan, kunci atau atribut membuat soal dikecualikan dari bukti terkalibrasi; nilai kuis tetap memakai snapshot sebenarnya. Perbandingan gap antarmodel berbeda tidak disimpulkan. Hasil lama tidak diam-diam diubah menjadi hasil baru.

Pelatihan ulang hanya ketika instrumen/data berubah dan memang diperlukan:

```sh
npm run train:ai
```

Perintah eksplisit ini mengekspor instrumen dari sumber konten dan membangun ulang **artefak sintetis EduBridge**. Tidak otomatis memasukkan edit dari database admin, tidak mengkalibrasi data sekolah nyata, dan tidak menimpa model EEDI/kalkulus. Untuk kalibrasi lapangan gunakan pipeline penelitian dengan data dan tinjauan pakar, lalu perbarui pemetaan instrumen serta artefak secara terkontrol. Jangan menjalankan training di request web.

## Gemini dan pendamping belajar

PDINA lokal menghitung diagnosis. Gemini hanya menyusun penjelasan materi dan narasi dari fakta diagnosis. Model API tidak menentukan nilai, probabilitas, gap atau XP. Narasi melalui validator fakta, cache, batas waktu dan circuit breaker. Jika key belum diisi, API gagal, atau narasi tidak sesuai fakta, aplikasi memakai ringkasan deterministik yang diberi label jelas. Pendamping konsep menggunakan materi lokal saat Gemini tidak tersedia. Kegagalan inferensi PDINA sendiri menghasilkan 503 dan mempertahankan jawaban untuk dikumpulkan ulang; tidak diganti dengan diagnosis buatan.

Data narasi menggunakan ID pseudonim dan fakta agregat. Nama/email akun dan kunci soal tidak dikirim ke Gemini. Email/nomor telepon pada pesan tutor disamarkan sebelum dikirim; pengguna tetap sebaiknya tidak memasukkan data pribadi. Tutor diblokir ketika asesmen topik tersebut sedang dikerjakan. Ringkasan siswa hanya dapat diakses pemilik hasil; ringkasan kelas dibatasi guru penanggung jawab/admin, fase pretest/posttest dan siklus terbaru.

## Rendering matematika

Persamaan dan notasi dirender dengan **KaTeX** pada teks soal, pilihan jawaban, pembahasan setelah pengumpulan, materi penguatan (contoh, langkah, latihan mandiri), pratinjau editor bank soal admin, jawaban tutor, dan narasi siswa/guru. Pecahan, akar, pangkat, indeks, komposisi/invers fungsi, himpunan, sudut, peluang, dan matriks tampil sebagai rumus; kalimat Indonesia tetap teks biasa.

- Bank soal memakai notasi Unicode (mis. `(x − 6)/2`, `√(13² − 5²)`, `f⁻¹(6)`, `[[2, 1], [3, 4]]`). Formatter `client/src/lib/mathText.js` mengubahnya menjadi LaTeX **hanya saat ditampilkan**. Teks soal, kunci, snapshot, Q-matrix, dan fingerprint PDINA tidak diubah, sehingga tidak perlu kalibrasi ulang.
- Konten baru dapat memakai delimiter `$…$`, `$$…$$`, `\(…\)`, atau `\[…\]` untuk rumus kompleks. Mengubah teks soal yang sudah dikalibrasi tetap membuat soal dikecualikan dari bukti terkalibrasi.
- Keluaran AI dirender sebagai Markdown tanpa HTML mentah dan tanpa gambar; tautan `javascript:` dibuang; KaTeX berjalan dengan `trust:false` sehingga `\href`, `\url`, dan `\html*` tidak menghasilkan tautan atau atribut. Pembaca layar menerima teks asli.
- KaTeX dimuat sebagai chunk terpisah; sebelum selesai dimuat, teks Unicode asli yang tetap terbaca ditampilkan.

## FastAPI / Swagger

Buka `/docs`, pilih endpoint, lalu **Try it out**. Schema menunjukkan request body, tipe field, response, validasi dan error. Bila `AI_SERVICE_KEY` terisi, pilih **Authorize** dan masukkan key pada header `X-Service-Key`. Key ini untuk operator/server, tidak untuk frontend siswa. Tanpa key, mode pengembangan hanya menerima pemanggil loopback. Produksi menolak startup tanpa key yang cukup kuat.

| Endpoint                    | Fungsi                                                           |
| --------------------------- | ---------------------------------------------------------------- |
| `GET /health`, `GET /ready` | Liveness dan kesiapan checkpoint                                 |
| `GET /v1/models`            | Versi/fingerprint, jumlah konsep/soal, kebijakan, asal kalibrasi |
| `POST /v1/diagnose`         | Diagnosis instrumen `edubridge`, `eedi`, atau `calculus`         |
| `POST /v1/compare`          | Perbandingan instrumen EduBridge, siswa/topik/model yang sama    |
| `POST /v1/narrative`        | Narasi hasil siswa atau guru, tervalidasi                        |
| `POST /v1/class-narrative`  | Narasi agregat satu topik/fase, maksimum 60 siswa                |
| `POST /v1/tutor`            | Pendamping konsep dengan konteks materi dan riwayat terbatas     |

Contoh body EduBridge (contoh parsial, sehingga bukti belum cukup):

```json
{
  "model_id": "edubridge",
  "topic_id": "fungsi",
  "student_id": "S-001",
  "responses": [
    { "question_id": "fun-pre-1", "answer_option": 1 },
    { "question_id": "fun-pre-2", "answer_option": null }
  ]
}
```

`answer_option` memakai indeks **0–3**. `null` berarti tidak teramati. Untuk EEDI/kalkulus, gunakan `question_id` numerik dalam string dan `response: 0`, `1`, atau `null`; jangan mengirim `answer_option` karena bank pilihan ganda lengkap tidak tersedia. `content_hash` memungkinkan backend memeriksa snapshot. `expected_model_version` menolak pembuatan ulang laporan historis dengan parameter berbeda.

## Auth, persistensi dan operasi

Password baru di-hash dengan scrypt asinkron, salt acak dan parameter tersimpan; hash lama ditingkatkan saat login. Sesi memakai token acak yang hanya disimpan sebagai hash di SQLite, cookie `HttpOnly`, `SameSite=Lax`, `Secure` pada produksi. Login merotasi sesi; logout, penggantian password, reset operator, dan penonaktifan akun mencabut sesi terkait. Terdapat pembatasan permintaan/login/AI, CSRF yang terikat sesi, pemeriksaan origin, peran dan kepemilikan, security headers, request ID, serta audit perubahan admin tanpa password/prompt.

Jawaban, deadline 15 menit, snapshot soal, versi diagnosis, siklus, XP dan progres disimpan server-side. Kunci/pembahasan tidak dikirim saat asesmen aktif. Pengumpulan ulang tidak menggandakan XP. Jawaban terakhir tetap dapat dinilai setelah deadline; jawaban terlambat tidak diterima. Gamifikasi tidak mengganti pengukuran pre/post.

Produksi memakai **satu instance Node** dengan volume SQLite persisten. Jangan membuat beberapa replika Node pada file SQLite/network filesystem yang sama; skala horizontal memerlukan migrasi database dan penyimpanan pembatasan permintaan terpusat.

Parameter password baru adalah scrypt `N=65536`, `r=8`, `p=2`, salah satu konfigurasi dalam [panduan OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). `TRUST_PROXY` hanya boleh aktif di belakang proxy tepercaya yang menimpa header forwarding; Compose contoh mengaktifkannya pada jaringan privat tanpa port API publik. Produksi menolak startup tanpa administrator aktif.

Antrean Node membatasi inferensi berjalan sambil menampung pengumpulan satu kelas. Pengujian mencakup 60 diagnosis serentak. Layanan narasi memakai kapasitas terpisah agar waktu tunggu Gemini tidak mengambil slot diagnosis; permintaan berlebih tetap menerima respons yang dapat dicoba ulang, dengan jawaban tersimpan.

Bootstrap produksi:

1. Siapkan `server/.env`: `NODE_ENV=production`, `SEED_DEMO=false`, origin HTTPS, path database baru persisten, dan secret antarlayanan.
2. Isi `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME`; jalankan `npm run setup:admin`. Akun yang sudah ada tidak ditimpa.
3. `npm run build`, kemudian `npm start` di belakang reverse proxy HTTPS. Buat guru sebagai admin, kelas sebagai guru, lalu siswa mendaftar dengan kode kelas.
4. Hapus password bootstrap dari konfigurasi setelah provisioning. Isi key/model Gemini saat tersedia, restart kedua layanan, lalu uji panggilan API langsung.

Backup konsisten menggunakan SQLite backup API:

```sh
npm run backup
```

Output default `server/data/backups/`; jadwalkan dan salin ke penyimpanan terpisah. Uji pemulihan secara berkala. Untuk memulihkan, hentikan aplikasi, simpan salinan database/WAL lama, pulihkan file backup ke `DATABASE_PATH`, lalu mulai ulang. Jangan menimpa database yang sedang digunakan.

Pemulihan password dilakukan operator yang memiliki akses server: set `RESET_EMAIL` dan `RESET_PASSWORD` (12–128 karakter), jalankan `npm run reset:password`, lalu hapus variabel tersebut. Operasi dicatat dan semua sesi akun dicabut. Pengiriman email reset/verifikasi tidak disediakan; siswa menghubungi pengelola sekolah.

## Deployment Docker + HTTPS

Siapkan domain/DNS dan `server/.env` produksi terlebih dahulu. Docker tidak tersedia pada lingkungan pengembangan yang digunakan untuk integrasi ini; build container/TLS harus diverifikasi pada host deployment.

```sh
docker compose --env-file server/.env build
docker compose --env-file server/.env up -d inference
docker compose --env-file server/.env run --rm app node src/setup-admin.js
docker compose --env-file server/.env up -d
```

Tambahkan `APP_DOMAIN=belajar.sekolah.sch.id` di `server/.env`, dan `APP_ORIGIN=https://belajar.sekolah.sch.id`. Caddy menyediakan HTTPS; API aplikasi/FastAPI tidak memiliki port publik langsung. Swagger tersedia di `https://belajar.sekolah.sch.id/diagnostics/docs`. Secret antarlayanan tetap diperlukan untuk endpoint AI. Volume database, cache/audit AI dan sertifikat persisten; container aplikasi berjalan tanpa root. Log/check: `docker compose --env-file server/.env logs` dan `docker compose --env-file server/.env ps`.

## Pengujian

```sh
# Dependensi tambahan untuk tes prototipe/penelitian asli
server/.venv/bin/python -m pip install -r server/ml/requirements-research.txt

npm audit --audit-level=low
```

Tes Node/browser memulai FastAPI terisolasi pada port acak, menggunakan database in-memory dan cache sementara. Gemini dinonaktifkan; respons SDK dan gangguan provider diuji tanpa biaya/panggilan luar. Google Chrome diperlukan untuk browser tests. Tes Python mencakup model/pipeline asli dan kontrak FastAPI. Tes berlabel live API memerlukan opt-in dan kredensial, sehingga tidak dijalankan pada verifikasi tanpa secret. CI tersedia di `.github/workflows/ci.yml`.

Uji Gemini langsung bersifat opt-in karena berbayar: `node scripts/live-check.mjs` hanya memeriksa kesiapan; `node scripts/live-check.mjs --confirm` melakukan tiga panggilan (tutor, narasi siswa, narasi guru) dengan data sintetis dan memperbarui `snapshots/live-verification.json` tanpa secret. Koneksi Gemini nyata sudah diverifikasi pada lingkungan pengembangan lokal (17 November 2026): ketiganya HTTP 200, `fallback=false`, dan kedua narasi lolos validator fakta. Screenshot dibuat ulang dengan `node scripts/capture-snapshots.mjs`, lalu `node scripts/build-snapshot-report.mjs` (database demo terisolasi; satu panggilan Gemini untuk tutor).

Yang masih memerlukan lingkungan deployment: rate/quota akun provider pada beban nyata, TLS/domain, build container Linux, backup/restore pada volume produksi, dan validasi instrumen menggunakan siswa nyata. Keberhasilan lokal tidak menggantikan pemeriksaan tersebut.

Rujukan implementasi: [FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/), [FastAPI API key security](https://fastapi.tiangolo.com/reference/security/), [Google Gen AI SDK](https://github.com/googleapis/python-genai). Catatan metodologi asli tersedia di `server/ml/README_pdina.md` dan `README_llm.md`.
